# Getting help and reporting a fault

Report a fault, or ask for something Volsa does not do, in the repository's
[Issues](https://github.com/Thenewmanator15/volsa/issues); a form asks for what is needed.

**Never attach a scan, a scan export, a label file made from a scan, or a screenshot that shows
patient details, and never paste tag values.** Anyone can read an issue. Describe what you saw
in words. Even with **Show patient details** off, the top bar and each viewport's corner show the
study's date and description, and a report may hold a name written some way Volsa cannot find.

Please include:

- **Volsa's version**, which the **About** window (in the **⋯** menu) shows.
- **Windows' version**: press Windows+R, type `winver` and press Enter.
- **The graphics device.** The log names the one Volsa draws with; Device Manager lists it under
  Display adapters.
- **`volsa.log`**, which the **About** window locates. It holds nothing about a patient and none
  of your file names, but read it before you paste it.
- What you did, what happened, and what you expected.

A security vulnerability is reported privately, never in an issue: see the
[security policy](https://github.com/Thenewmanator15/volsa/blob/main/SECURITY.md), or report it
[here](https://github.com/Thenewmanator15/volsa/security/advisories/new). To work on Volsa, see
[CONTRIBUTING.md](https://github.com/Thenewmanator15/volsa/blob/main/CONTRIBUTING.md) and
[[Building from source]].
